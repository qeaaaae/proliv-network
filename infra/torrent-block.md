# Торрент-блок на нодах: попытка и откат (2026-11-15/17)

## Что было сделано и откачено

2026-11-15 во все 7 config profiles добавили `{"type":"field","protocol":["bittorrent"],"outboundTag":"reject"}`
(через `PATCH /api/config-profiles`). 2026-11-17 выяснилось, что xray 26.7.28
на нодах не имеет нативного bittorrent-сниффера - правило никогда не матчится,
мёртвый конфиг. Правило удалено из всех профилей, профили = состояние до 15.11
(минус это правило; reject-правила lan-freeze-fix на месте).

## Инцидент 15.11 (на память)

Попытка добавить `"bittorrent"` в `sniffing.destOverride` уронила все 9 нод
на ~3 мин: значение невалидно для destOverride, xray не стартует с таким
конфигом. Откат destOverride восстановил ноды сам. Вывод: sniffing-правки
проверять на одной ноде, не пачкой.

## Алерт-система (откачена 17.11)

Параллельно пилотировался монитор на KZ-ноде (`torrent-ban-monitor.py` +
systemd, DHT-burst эвристика -> webhook -> TG-алерты админам с кнопками ->
iptables на ноде). Снесено полностью: сервис/скрипт/iptables-правила на KZ,
вебхук и handler в shop (исходники откачены, контейнеры пересозданы из
образа), ключ TORRENT_ALERT_API_KEY выпилен из settings (строка в shop/.env
осталась, settings её игнорирует - extra="ignore"; можно удалить руками).
Причина отката: эвристика детектит плохо, бан шёл по IP (задевает соседей
по CGNAT), персистентности банов нет, алерты без дедупа. Если возвращаться -
сначала решить эти вопросы, потом KZ-пилот заново.

## Актуальное решение: Remnawave Torrent Blocker plugin (с 17.11)

Встроенный плагин ноды (НЕ самопис). Требования: Node v2.7.0+ / Xray 26.3.27+,
у нас node 3.4.3 + xray 26.7.28 - подходит.

- Плагин `8794c237-8543-4261-992f-fa3b5af495b8` создан через
  `POST /api/node-plugins` (`torrentBlocker.enabled=true`,
  `blockDuration=3600` - бан IP юзера на час через nftables на ноде).
- Привязан `activePluginUuid` ко всем нодам через `PATCH /api/nodes`
  (см. `infra/remnawave-api.md`). С 21.11 плагин включён и на новых
  `EE2-Node-01`/`EE2-Node-LTE` (qwins).
- Детект = штатный xray-сниффер bittorrent (в 26.7.28 ЕСТЬ - вывод
  «сниффера нет» от 15.11 был неверен, тогда крашился невалидный
  `destOverride`, а не сниффер).
- Статистика/reports в панели. TG-уведомлений нет (нужен бот в
  настройках remnawave-панели, не минишопа).
- **На NL плагин снят 17.11** - `PluginService batch error: No such
  file or directory` в логах remnanode. Юзеры не пострадали, но плагин
  там не работает. Причина не исследована (возможно несовместимость
  с NL-Profile-v2).

## Что осталось работать

- Клиентский шаблон подписки: `bittorrent -> direct` (торренты идут мимо VPN
  через ISP юзера, серверы не нагружаются) - в `infra/lan-freeze-fix.md`.
- `reject`-аутбаунд и reject-правила в профилях (private IP, SMB,
  discovery-порты) - не относятся к торрентам, оставлены.
- Бэкап профилей до bt-правки: `/root/proliv-bt-block-backup-20261115.json`
  на proliv-main (содержит состояние ДО lan-freeze... точнее слепок на
  момент 15.11 с bt-правилом до его удаления - для истории).
